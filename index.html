Gezielt Bits verändern

Tippen Sie auf ein oder mehrere empfangene Bits; auch das Prüfbit kann fehlerhaft sein.

Warum erkennt Parität nicht jeden Fehler?

Ein einzelner Bitwechsel ändert gerade in ungerade Parität. Zwei Bitwechsel erhalten die Parität. Der Empfänger kennt nur das empfangene Wort: Passende Parität bedeutet „kein Paritätsfehler erkannt“. Sie beweist keine fehlerfreie Übertragung und verrät keine Fehlerposition.

Ein Bit umkehren

PRÜFEN → LOKALISIEREN

Prüfgruppen sichtbar machen

Klicken Sie eine Gruppe an: Die beteiligten Positionen werden markiert.

Gültigkeitsgrenze: Wir nehmen höchstens einen Bitfehler an. Nur dann gibt ein von 000 verschiedenes Syndrom die Fehlerposition an. Probieren Sie auch zwei Fehler aus: Das Verfahren kann dann ein falsches Bit umkehren. Die rot markierten Unterschiede zum Sendewort sind eine Hilfe der Simulation; der Empfänger kennt das Sendewort nicht.
Prüfbits und Syndrom schrittweise erklärt
  1. Die Positionen 3, 5, 6, 7 erhalten die vier Datenbits.
  2. Wählen Sie p₁, p₂ und p₄ so, dass jede Prüfgruppe eine gerade Anzahl von Einsen enthält.
  3. Beim Empfang gilt s = 0 bei gerader und s = 1 bei ungerader Anzahl.
  4. Lesen Sie das Syndrom als s₄s₂s₁: F = 4s₄ + 2s₂ + s₁.
  5. Bei höchstens einem Fehler: F ≠ 0 nennt die Position, deren Bit umgekehrt werden muss.

AUFGABE 3 · POSITIONEN ERFASSEN

Ein Übergang. Zwei Codes.

Ein Positionsgeber schaltet von einem Wert zum nächsten. Seine Spuren wechseln geringfügig zeitversetzt.

15 Min.
Warum ein anderer Code? Ein Geber erfasst die Position über vier Spuren. Beim Übergang 7 → 8 müssen im Dualcode alle vier Spuren wechseln. Werden sie zeitversetzt gelesen, kann ein falscher Zwischenwert entstehen. Beim Gray-Code wechselt zwischen benachbarten Positionen nur eine Spur: Im idealisierten Modell liest man den alten oder den neuen Nachbarwert.
DUALCODE · GEWICHTE 8 / 4 / 2 / 1

Dual

GRAY-CODE · EIN BIT PRO SCHRITT

Gray

Modell: Dualspuren wechseln einzeln in der gewählten Reihenfolge. Die tatsächliche Reihenfolge kann anders sein. Beim vollständigen reflektierten Gray-Code wechselt auch am Umlauf 15 → 0 nur ein Bit. Gray erkennt oder korrigiert keine beliebigen Übertragungsfehler; reale Geber können weitere Fehlerquellen haben.
ZWISCHENWERTE VERGLEICHEN

Was liest die Steuerung während des Übergangs?

Die Zeilen sind einzelne Schaltvorgänge, keine gemeinsamen Zeitpunkte beider Geber. Die Gray-Spur kann früher oder später umschalten. Entscheidend ist: Es entsteht kein Mischwort aus mehreren wechselnden Spuren.

UMWANDLUNG · AUSGEWÄHLTE STARTPOSITION

Dual → Gray → Dual

b bezeichnet ein Dualbit, g ein Gray-Bit. Index 3 steht links, Index 0 rechts. XOR (⊕): gleiche Bits → 0; unterschiedliche Bits → 1.

Gray-Bits haben keine festen Gewichte. Deshalb wird z. B. Gray 1100 zuerst in Dual 1000 zurückgewandelt und ergibt Position 8.

Codefolge und Umwandlung aufdecken

g₃ = b₃; g₂ = b₃ XOR b₂; g₁ = b₂ XOR b₁; g₀ = b₁ XOR b₀. XOR ergibt bei gleichen Bits 0, sonst 1. Gray hat keine festen Stellengewichte.

AUFGABE 4 · BCD-ADDITION

Warum wird sechs addiert?

Die Anzeige am Werkzeugschlitten verarbeitet jede Dezimalziffer einzeln.

20 Min.

Korrekturregel und Begründung

Vier Bits zählen dual von 0 bis 15. Eine Dezimalziffer darf nur 0 bis 9 sein. Die Differenz der Stellenbasen beträgt 16 − 10 = 6.

Rohsumme größer als 9: Addieren Sie 0110. Das ist nötig, wenn die unteren vier Bits eine Pseudotetrade ergeben oder bereits ein Übertrag aus dem Vierbit-Addierer entsteht. Die unteren vier korrigierten Bits ergeben die Ziffer. Der Dezimalübertrag wird an die nächste Stelle weitergegeben.

9 + 8 = 17 ergibt roh 1 0001. Obwohl die unteren Bits 0001 gültig aussehen, ist wegen des Übertrags die Korrektur erforderlich: 1 0001 + 0 0110 = 1 0111 → Ziffer 7, Übertrag 1.

AUFGABE 5 · BCD-SUBTRAKTION

Subtrahieren mit einer Addierschaltung.

Zwei Dezimalstellen: Ergänzen auf 100 und anschließend addieren.

20 Min.

Warum funktioniert das Komplementverfahren?

Neunerkomplement: jede Ziffer auf 9 ergänzen. Zehnerkomplement: zusätzlich 1 addieren. Für B ≠ 0 gilt bei zwei Stellen K₁₀(B) = 100 − B.

A + (100 − B) = 100 + (A − B). Bei A ≥ B entsteht ein Hunderterübertrag: Verwerfen Sie ihn. Bei A < B bleibt ohne Übertrag die Komplementdarstellung eines negativen Ergebnisses. Bilden Sie erneut das Zehnerkomplement des Restwerts, um den Betrag zu erhalten, und setzen Sie ein Minuszeichen davor.

Sonderfall B = 0: Das Zweistellen-Zehnerkomplement von 00 ist modulo 100 ebenfalls 00. Es wird direkt A + 00 = A gerechnet; kein Übertrag ist erforderlich.
